### The review's findings, and what was done

- **F1 (major), fixed.** The no-rejection-region clause printed α/m as "at level α = <α/m>", so one sentence
  gave α two values; read with its own α, it said no outcome at this n could be met, when in a Holm family one
  can (clearer at 6 wins of 6 is met beside faster). It now reads "at level α/m = <level>", D2's words with
  the level named as D3 names it; the exact wording is vetoable. Test:
  `test_the_level_with_no_rejection_region_is_named_alpha_over_m`, which also requires every "α = " in the
  sentence to be the hypothesis's alpha.
- **F5, fixed.** `evaluate` read each used unit's outcomes three times (check, count, hash), so a mapping that
  answers differently when read again gave counts the hashed data does not. It now copies them once
  (`_outcomes_read_once`) and uses the copy throughout. Test: a two-faced mapping's evaluation equals that of
  one plain dataset or the other.
- **F7, fixed in part.** `record_read` kept a relative `reads_path` as spelled, so after a change of directory
  `render` refused the very file. It now resolves the path when it records, and `receipt_from_line` does the
  same, so the two receipts of one read stay equal. The case-spelling half was left to the maintainer, who
  kept it (E5).
- **T1 (major), fixed.** The lock test showed only that the append waits for the lock. A new test lets a
  second writer's read land while `record_read` waits for the lock and requires the seal to refuse on it. It
  waits on a watched `fcntl.flock` call, not a sleep, so moving the flock after the seal fails it every time.
- **T2 to T7, fixed.** New tests: a read equal to the first read but not to a later re-read is sealed (T2); a

- **For the maintainer:**
  - E3 says nothing in an early read's sentence hints at the result, yet it still carries p, the family's
    adjusted p, and α, from which the verdict can be worked out. Keep them, or withhold them on an early read
    too? Amendment 3 records the gap.
  - R4, E2 at the boundary: when the MDE lies within one rounding step of 1 (or of 0, below the null), the gap
    rounded up to four significant digits passes it; at p0 = 0.33330001, n = 2400, and an alpha below p0 to the
    2400th power, the sentence prints "0.33330001 + 0.6667", above 1, and `mde_text(Fraction(1, 3), 1.0)` gives
    "1/3 + 0.6667". There no gap of four significant digits both reaches the power and keeps the effect within
    the boundary. Cap the effect at the boundary with the exact gap ("1/3 + 2/3"), keeping the power but not the
    four digits; round that gap toward the null, keeping the digits but not the power; or print the effect
    itself there? Only an absurdly small alpha reaches it.
  - E1 reads line by line, so a stale copy hard-wrapped over lines passes (C6, R2). Keep that as a recorded
    limit, or widen the check past lines (a paragraph, say), which E1 did not decide?
- **Choices the spec did not make (vetoable):**
  - Numbers: p-values are printed to four significant digits, rounded half to even from the exact fraction;
    alphas and p0 are printed exactly (a finite decimal, else "a/b"). These pin sentences once released.
  - `render` does not compare `as_of` with the line. It refuses when any line of the reads file is malformed.
  - E1's details: a sentence `render` did not return, or one that spans lines, raises ValueError; a line names
    the name or the id where it stands as a word, only the id inside another rendered sentence's body, and the
    name not inside the id; a document quoting a read and the re-read that superseded it fails for each; lines
    are `str.splitlines`'s.
  - The sentence's one line is enforced in render, as a PreregError, not in load: load still accepts a name or
    family holding a line break, so such a record can be read but never rendered. Refusing it at load too would
    change what prereg/1 accepts.
  - E6's error is NotImplementedError, not PreregError, since a platform without fcntl is not a refusal of
    the read.
