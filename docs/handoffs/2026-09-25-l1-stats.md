## Done this session

  - `binomial`: `binom_pmf`, `binom_tail`, `binomial_test` (two-sided only at p = 1/2), `sign_test`,
    `paired_sign_test` (missing values refused or dropped, never silently), and `mcnemar_exact`.
  - `intervals`: `wilson` and `clopper_pearson`, both refusing n = 0.
  - `multiplicity`: `holm`, `benjamini_hochberg`, and `Family`, which refuses undeclared members and
    incomplete adjustment.
  - `power`: `rejection_region`, `binomial_power` and `sign_test_power`, `binomial_mde` and `sign_test_mde`,
    and `sequential_size`, the true size of a peeking schedule.
  - `decide(result, alpha)` rejects iff the exact p-value is at most alpha. Floats are refused as alpha or as
    p-values.
- **Calling convention.** `alternative`, `method`, `missing`, and `correction` are keyword-only with no
  default, and every test takes `method="exact"`. The freeze rule needs `method` to exist from the first
  release: adding it later would need a default. `ApiRuleTest` pins this. The maintainer approved this
  convention on 2026-09-25, so later modules follow it.
- **Oracles in the gate:**
  - every outcome sequence for n <= 14;
  - exact size <= alpha for n <= 200 at alpha in {0.01, 0.05, 0.10}, all three sides;
  - Clopper-Pearson coverage >= nominal on a 1001-point grid;
  - brute-force peeking over 2^12 sequences.
- **Properties:** 10 Hypothesis properties under a deterministic profile (200 examples).
- **Reference fixture:** `make reference` pins scipy 1.18.1 and statsmodels 0.15.0. The fixture has 234
  cases and a drift test against the script's sha256.
- **Simulation:** `make sims` gives 5 cases of 20000 runs, each required to lie within 3 standard errors of the
  exact figure.
- **Mutants:** 53 new, one per guard (19 in the first commit, 22 from the first review's fixes, 12 from the

## Review fixes

An adversarial review of PR #3 (a statistics reviewer and a checks reviewer) found the defects below. Each fix has a test that failed before it, and a
mutant.

- `0c77891`: pins one-sided McNemar. `Family.decide` decides on the adjusted p-values. BH is tested on a
  family of three.
- `7648c0b`: the reference fixture is checked case by case against the script. Its header's scipy and
  statsmodels versions are checked against the Makefile's pins.
- `5634789`: `wilson` takes `confidence` or `z`, not both. `z` must be a finite positive quantile, and the
  interval records the confidence it implies. Confidence and power targets of 0 or 1 are refused.
- `442b47f`: the Clopper-Pearson upper bound is solved by symmetry, so the tail crossing is exact to two ulps.
- `d639b70`: exact tails are linear in n (a cached half row at 1/2, and a stepped coefficient elsewhere). A
  one-sided test computes only its own tail. A sign test on 20000 pairs went from 55 s to 0.1 s.
- `3c765b6`:
  - `binomial_mde` refuses a test that reaches the target power with no effect; it used to return p0.
  - The rejection region is found by bisection.
  - The MDE search runs in floats, moved outward by a margin. The MDE of 1000 pairs went from 126 s to under
    0.1 s.
  - Scale tests now fail when their budget runs out, not when the work ends.
- `a76f693`: `paired_sign_test` treats a Decimal NaN as missing, and refuses a value that is not a real number
  (a string, bytes, complex, or bool) with a TypeError naming its position.
- `d27df6a`: a string that is not an exact number (`"nan"`, `"inf"`, `"1/0"`) is a ValueError naming the
  argument.

A second review, of those fixes alone, found the defects below; `69faf9a` fixes them, each with a test and a mutant.

- **Blocking:** `binomial_mde` fell short of its target by up to 2e-14 at power targets of about 0.9999999 and
  above, where the float power's rounding outweighed the 1e-9 outward margin. The answer is now a multiple of
  2^-30, found by the float search and then settled exactly: the exact power there reaches the target, and at
  the next multiple toward p0 it does not. Near power 1 the float search sums the missed mass instead. The
  exact settling is its own function, `_settle`, tested from every kind of guess.
- A general-p tail kept every power of 1 - p (14 MB at n = 2000 from a float p); it is now summed by Horner's
  rule in constant space, and a run of counts from 0 costs one tail, not two.
- Time budgets widened to survive a loaded CI runner (the MDE at scale, 15 s). The one-sided speed test moved
  to n = 20000, where its mutant takes 44 s, and a mock now pins that a one-sided test computes one tail.
- `wilson(z=...)` refuses a bool, a string, or an exact number.
- The `why` of `a_non_number_compared_as_it_is` now names the reason the mutant actually dies for.

A re-review of `69faf9a` found no correctness regression: 3334 designs checked exactly, none short of the
target or not the nearest grid point. It found two speed paths unpinned; `0d9a2b6` counts each with a mock
(3 exact evaluations near power 1 instead of 40 to 60, and one tail for a run from 0), each with a mutant.

## Open

- **Nits from the second review, left as they are:**
  - `within` (the tests' time budget) uses SIGALRM, so the scale tests cannot run on Windows, and a nested
    `within` would switch off the outer budget; no test nests them, and CI runs on Linux.
  - The confidence `wilson` records for a given `z` is the float-derived fraction z implies.
  - `exact()` accepts what `Fraction(str)` does, including Unicode digits and underscores (`"1_0"`).
  - A target within about 1e-308 of 1 (so 1 - target is 0.0 as a float) makes the MDE settle by about 50
    exact evaluations instead of 3; still correct, and about 7 s at n = 5000.
  - `wilson(z=10**400)` raises OverflowError rather than the documented ValueError, as it did before.
