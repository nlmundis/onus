## Done this session

- `onus/prereg/`:
  - `load(path)` checks every field of a `prereg/1` record. It refuses:
    - keys the schema does not define, and missing keys, at every level; repeated keys;
    - floats, NaN, and exact numbers that are not plain ASCII (`"0.05"`, `"1/3"`);
    - a lone surrogate anywhere, and JSON too large or too deep to read;
    - a `cluster_key` (v0.2), and `looks` other than the horizon alone;
    - a days window that opens before `registered` or runs past the last date;
    - a bound artifact that is not a plain path resolving inside the record's folder, is missing, or has
      changed.
  - `prereg_id(path)` is `<stem>@<sha256[:12]>`.
  - A `Rule` keeps its record's bytes, and `evaluate` and `record_read` refuse one that no longer matches them.
    Its mappings are read-only, so a `Rule` cannot be pickled or deep-copied.
  - `evaluate(rule, data, *, as_of=None)` reads no clock and writes nothing. A count horizon uses exactly the
    first N units by `order_key` and refuses repeated order values; a days horizon needs a `date` as_of past
    its window and uses the units dated inside it. Each hypothesis states its test, method (`"exact"`), alpha,
    family, and for a binomial test p0; each declared family is decided on its adjusted p-values.
  - `status` gives "pending" before the horizon, then met / not met.
  - `record_read` appends a `read/1` line and returns a receipt. It refuses an evaluation of another rule, one
    whose families, alphas, or labels the rule and its adjusted p-values do not give, and a reads file whose
    last line was cut short.
- `tests/test_prereg.py`: 24 tests, synthetic records only; `onus/prereg` at 100% branch coverage.
- 27 mutants under "pre-registration" in `mutt_check.toml`, each run alone and caught by the test it names;
  they include the spec's "horizon not enforced", "evaluate uses more than the first N or ignores order_key",
  and "unknown prereg key accepted".

  horizon alone; each hypothesis states `method`; a days window may not open before `registered`;
  `Rule` holds read-only mappings, so it cannot be pickled.
- **Known limits:** `record_read` takes no lock, so one process at a time should write a reads file; it cannot
  re-check an evaluation's counts without the data. String `order_key` values sort as text ("10" before "2").
  A sign test whose used units are all ties, or an empty days window, raises `EmptySampleError`.
